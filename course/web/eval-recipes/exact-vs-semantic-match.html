Exact-match vs semantic-match scoring

Output correctness

correctness starter
When to use: When choosing how to score a regression eval — exact for structured outputs, semantic for prose.
What it measures: Output equivalence, with different tolerances for surface variation.

Setup

  1. Classify each eval case by output type: structured (JSON, code, IDs) → exact; prose → semantic.
  2. For exact: compare normalized strings or parse + compare ASTs.
  3. For semantic: use embedding cosine similarity threshold (≥ 0.85) OR LLM-judge.
  4. For numeric: use tolerance windows (e.g., ±2% for dollar amounts).
  5. Log which scoring mode was used per case for auditability.

Code template

typescriptimport { cosine } from "./embedding.js";

export type Scorer = (expected: string, got: string) => Promise<number>;

export const exactScorer: Scorer = async (e, g) =>
  e.trim().toLowerCase() === g.trim().toLowerCase() ? 1 : 0;

export const semanticScorer = (threshold = 0.85): Scorer => async (e, g) => {
  const [ev, gv] = await Promise.all([embed(e), embed(g)]);
  const sim = cosine(ev, gv);
  return sim >= threshold ? sim : 0;
};

export const numericScorer = (tolPct: number): Scorer => async (e, g) => {
  const [a, b] = [parseFloat(e), parseFloat(g)];
  return Math.abs(a - b) / Math.abs(a) <= tolPct ? 1 : 0;
};

Acceptance threshold

Per case-type aggregate ≥ 0.95; mixed sets weighted by case-type prevalence.

Pitfalls

⚠️ Exact-match on prose causes near-100% failures from punctuation drift
Fix: Always semantic for free-form text.
⚠️ Semantic threshold too low → false-positive 'matches'
Fix: Anchor the threshold on a labeled subset where you know matches from mismatches.
