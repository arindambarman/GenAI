Citizen FAQ co-pilot (high-volume, low-cost)

City services portal · Public Sector

Cost optimization starter

Situation

A city portal handles 1.8M FAQ queries/year on garbage collection, permits, benefits eligibility, etc. Current system is keyword search with 31% deflection; remainder go to a 20-person call center. Budget pressure is intense — any solution must come in under $25K/year API cost.

Problem

Push deflection to 60% with answers that cite the official source policy, on a hard API budget of $0.014 per query (≈$25K/year).

Approach

  1. 7-block prompt with the entire small-corpus FAQ + recent policy updates cached at the prefix (city policy corpus is ~80K tokens — caches well).
  2. Haiku as the only model — no escalation tier. Cost is the binding constraint.
  3. Citations API: every answer links back to the official policy page; this is the trust signal that lets the city stand behind the answer.
  4. Semantic cache: ~40% of queries are textual variants of the top 200 questions; cache hits return frozen answers at $0 LLM cost.
  5. If the model's confidence is low or the question is out-of-scope, return a 'this question needs a human' card with the call center number — never invent.
  6. Weekly regression eval on 100 representative queries graded by city staff.

Trade-offs (what we ruled out)

Ruled out: Sonnet escalation tier
Cost ceiling forbids it; Haiku + caching + handoff for unsure cases hits the deflection target close enough.
Ruled out: Full agentic RAG
Overkill for a small static corpus; cached corpus + single-pass beats RAG on both latency and cost.
Ruled out: Open answer style without citations
Public-sector trust requires source attribution; non-negotiable.

Eval criteria

Deflection ≥ 60% measured by no-call follow-through · API cost ≤ $0.014/query · Citation faithfulness 100% · Quarterly staff-graded accuracy ≥ 95%.

Rollout plan

Backfill against 6 months of past queries with known resolutions (4 weeks) → 10% live traffic A/B (8 weeks) → full rollout with prominent 'still need help?' link (ongoing).
