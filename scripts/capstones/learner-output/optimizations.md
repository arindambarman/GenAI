# Course Optimization Suggestions
Generated by the Learner Agent. 10 total.

## HIGH priority (4)

### 1. [missing_example] Lessons 1.3
- **Current:** The agent-vs-workflow-vs-pipeline decision framework is described as five questions but no worked example is given showing how HSBC reconciliation, Helix research, or Acme E-Commerce would apply these questions.
- **Suggestion:** Add a worked example showing one of the three World Bible organizations applying the five-question framework, demonstrating the decision process and justifying why agent (or workflow) was chosen with concrete cost/autonomy numbers.
- **Why:** Learners need to see the framework applied to concrete problems before they can apply it themselves. Especially important for a decision framework that aims to prevent the "use an agent when workflow suffices" anti-pattern (module objective 5).

### 2. [missing_practice] Lessons 1.4
- **Current:** Four major paradigms are described (ReAct, Reflexion, Plan-and-Solve, CodeAct) with failure modes mentioned but learners have no exercise to match failure modes to paradigm choices or to select appropriate paradigms for novel problems.
- **Suggestion:** Add a classification exercise: give 5-6 agent task descriptions (e.g., "agent must handle exceptions without replanning", "agent must learn from repeated mistakes", "agent must compose complex tool sequences") and ask learner to select the best paradigm(s) and justify using the failure modes.
- **Why:** Paradigm selection is a critical skill but passive reading of paradigm descriptions is insufficient. Module objective 4 says 'recognize and use' but only recognition is taught.

### 3. [weak_explanation] Lessons 1.1
- **Current:** Agency dial is presented as a 0-4 scale with 'four properties,' but the module text provided does not explicitly define each level (0, 1, 2, 3, 4) or the four properties.
- **Suggestion:** Explicitly define each level of the agency dial with concrete examples: Level 0 (pure LLM, no loops), Level 1 (single tool call), Level 2 (ReAct loop), Level 3 (reflection/planning), Level 4 (hierarchical multi-agent). Show World Bible examples at each level.
- **Why:** The agency dial is central to the module's learning objectives, and learners need clear, actionable definitions to apply it. Ambiguity here cascades to the decision framework (1.3).

### 4. [missing_practice] Lessons 1.3
- **Current:** Learning objective 5 says 'Avoid the most common mistake: using an agent when a workflow would do,' but no exercise or assessment is provided to test whether learners can make this distinction.
- **Suggestion:** Add a quiz or problem set with 5-10 domain descriptions (e.g., 'daily ETL pipeline,' 'customer support triage,' 'research hypothesis generation'). Learners decide whether each should be a pipeline, workflow, or agent and justify using the five-question framework and agency dial.
- **Why:** This learning objective is about developing judgment and avoiding costly mistakes. Without practice, learners may not internalize the decision criteria or may default to agents (over-engineering). Practice tests competency.

## MEDIUM priority (5)

### 1. [weak_explanation] Lessons 1.2
- **Current:** The lineage from symbolic agents to RL to LLM agents is described historically but the course doesn't explicitly explain which concepts from RL (like MDPs, exploration-exploitation, value functions) actually reappear in modern LLM reasoning.
- **Suggestion:** Add a forward-reference note in lesson 1.2 pointing out that concepts like MDPs and partial observability (POMDPs) from RL agents are re-examined formally in Module 2, and that techniques like curiosity-driven exploration map onto information-theoretic agent strategies discussed later.
- **Why:** Helps learners see continuity across the historical narrative and understand why Module 2 (math) is foundational, not optional. Bridges historical and formal frameworks.

### 2. [cross_module_link] Lessons 1.1, 1.3
- **Current:** The agency dial (1.1) and the agent-vs-workflow decision framework (1.3) are conceptually related but the module doesn't explicitly show how to translate agency dial scores (0-4) into concrete cost/autonomy tradeoffs used in the decision framework.
- **Suggestion:** Add a section at the end of 1.3 showing a table: Agency Dial level (0-4) → expected token costs → autonomy gains → typical cost-per-error. Make this concrete by referencing the World Bible (HSBC breaks, Helix citations).
- **Why:** Learners need to see the connection between philosophical framework (agency dial) and practical decision-making (agent-vs-workflow) to internalize both. Helps with module objective 3.

### 3. [sequencing] Lessons 1.2
- **Current:** Lesson 1.2 (Brief History) assumes learners can follow narrative about symbolic agents (1956) → RL agents (1990) → LLM agents (2022) but foundational definitions like MDP aren't introduced until Module 2.
- **Suggestion:** In lesson 1.2, when introducing RL agents, add a sidebar or footnote defining MDP at a very high level (state-action-reward) and explicitly defer the formal treatment to Module 2. This prevents two issues: confusion from undefined terms, and the perception that history is disconnected from math.
- **Why:** Learners need basic vocabulary to follow the historical narrative. A 1-sentence definition of MDP unblocks comprehension without requiring Module 2 upfront. Also prevents skipping Module 1.2 as too vague.

### 4. [missing_example] Lessons 1.3
- **Current:** The five-question framework for agent vs workflow vs pipeline is mentioned with references to 'cost of agency' and vendor choices, but no worked example is provided showing the decision tree applied to a real scenario.
- **Suggestion:** Add a worked example using one of the three World Bible organizations (HSBC, Helix, Acme) applying the five-question framework to decide whether an agent or workflow is appropriate. Show the cost/benefit tradeoff explicitly.
- **Why:** The framework is a critical decision tool for practitioners. Without a concrete example, learners may not internalize how to apply it. Using World Bible organizations builds continuity and helps learners see agents in realistic context.

### 5. [missing_example] Lessons 1.4
- **Current:** Four major paradigms (ReAct, Reflexion, Plan-and-Solve, CodeAct) and their failure modes are defined, but no side-by-side comparison or worked examples showing how each paradigm would solve the same problem differently.
- **Suggestion:** Create a comparison matrix or worked example (e.g., solving a multi-step research task using Helix scenario) where the same query is attempted with each paradigm, showing outputs, failure modes, and token costs. Include concrete code snippets or pseudo-code for each.
- **Why:** Paradigm selection is a core design decision, but learners need to see how each behaves on real tasks to develop intuition. Worked examples aid transfer learning to new domains.

## LOW priority (1)

### 1. [cross_module_link] Lessons 1.2
- **Current:** The lesson traces symbolic agents (1956-1990), RL agents (1990-2017), and LLM agents (2022+), but the connection to MDPs/POMDPs (Module 2) is not explicitly mentioned, though it's crucial for understanding the RL era.
- **Suggestion:** Add a forward reference in 1.2 noting that the RL agents era was formalized using Markov Decision Processes (MDPs), and that modern agents still inherit MDP thinking (state, action, reward). Provide a 1-2 sentence teaser on why this formalism matters (covered in Module 2).
- **Why:** Learners encountering Module 2 will see MDPs introduced without understanding why they're relevant to agents. Explicit forward-reference helps them see the lineage and builds narrative cohesion.
